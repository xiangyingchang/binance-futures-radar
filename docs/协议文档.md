# UAIUSDT 15 分钟做空监控协议

- 状态：已部署、验证并完成审查加固
- 目标：每 15 分钟扫描 Binance USDⓈ-M `UAIUSDT` 永续合约；仅在做空判断状态、触发位/失效位风险带或数据质量发生重要变化时，通过飞书发送一条可审计的纯文本判断。
- 任务调度：`*/15 * * * *`，使用 Hermes Cron 默认本地时区（Asia/Shanghai）。
- 运行方式：只读行情分析，不下单、不改仓、不读取账户资产或密钥。

## 1. 数据口径

- 主来源：Binance Futures API 的 `www.binance.com/fapi` 入口；不使用现货价格代替期货价格。
- 使用字段：24h ticker、mark/index price、funding interval、当前/90 日资金费率、1H/4H/1D K线、1H OI 历史和当前 OI。
- 市场环境：使用生产环境 `/api/market` 的 Binance-fapi 宽度口径作为背景，不以第三方搜索摘要作为交易数字。
- 每轮必须记录各接口时间戳：HTTP `Date`、ticker `closeTime`、premium/index `time`、当前 OI `time`、K线的 `openTime/closeTime`、资金费率和 OI 历史的最新时间，以及市场 relay 的 `generatedAt`；关键数据任一缺失、请求失败、未来时间或超过 180 秒，状态为 `DATA_ERROR`。
- 资金费率分位使用接口返回的完整可用 90 日历史，并先读取该合约的 `fundingIntervalHours`；禁止默认按 8 小时年化。

## 2. 计算口径

- RSI：Wilder RSI(6)，分别计算 1H、4H、1D；live RSI 只作热度参考，结构判断使用已收盘K线。
- OI：按 1H 快照计算当前相对 24 小时、7 天前的合约数量变化。
- 4H 结构破位：已收盘 4H K线收盘价低于前一根已收盘 4H K线低点。
- 1H 结构破位：已收盘 1H K线收盘价低于此前三根已收盘 1H K线最低点。
- 1H 初步反转：当前已收盘 1H RSI(6) <80，且此前 12 根已收盘 1H RSI(6) 曾 >90。
- 失效参考：最近 6 根已收盘 4H 最高点 + 0.5 × 4H ATR(14)。该值是风险参考，不是自动订单价格。
- K线的 `open/high/low/close` 和时间字段必须全部为合法有限数值，坏行不得用 `0.0` 回退；坏数据直接进入 `DATA_ERROR`。

## 3. 判断状态

监控状态是确定性的，写入 state monitor 的输出以便 Cron 做变化检测：

- `DATA_ERROR`：关键数据不可用或过期；必须发送“数据异常；不调仓、不新增仓位、不执行交易”。
- `INVALIDATED`：价格达到/超过失效参考或重新突破近期高点；明确不空。
- `SHORT_CONFIRMED`：资金费率分位 >=P90、4H 收盘有效破位、至少有 1H 初步反转或 4H RSI 下降/背离，且没有数据异常；仍需人工催化剂审查，不能自动交易。
- `WATCH_EXTREME`：资金费率分位 >=P90，但 4H 尚未收盘破位；只观察，不新开空。
- `WATCH_COOLING`：出现 1H/4H 降温或初步反转，但资金费率/结构未同时满足确认条件；只观察。
- `NO_SETUP`：上述条件均未满足；不新开空。

OI 快速增长（24H >=20% 或 7D >=30%）标记为 `SQUEEZE_RISK`。有该标记时不得把报告升级为“可以做空”，除非后续仍有收盘破位并明确提示逼空风险。

## 4. 推送门槛

- 每 15 分钟都扫描。
- 只有以下事件推送飞书：状态变化、`SQUEEZE_RISK` 开关变化、1H/4H 结构确认变化、触发位/失效位风险带变化、数据异常/恢复。
- 仅价格小幅波动、指标数值变化但状态未变时不推送，避免每天 96 条通知。
- 触发或失效价必须标明“收盘确认”与“盘中插针不算”。
- 推送内容先给结论，再给关键指标、触发条件、失效条件、数据时间和“发布状态”。
- 所有报告必须明确 `autoTrade=false`，不得输出下单动作或虚构账户仓位。
- `SQUEEZE_RISK` 必须在报告文字中明确写出“逼空风险高”，不能只输出布尔值。

## 5. 实现与运行文件

- 版本化协议：`docs/协议文档.md`
- 版本化脚本：`scripts/hermes/uai_short_monitor.py`、`scripts/hermes/uai-short-monitor.py`、`scripts/hermes/uai-short-monitor-state.py`
- Cron 实际脚本：`~/.hermes/scripts/uai_short_monitor.py`、`~/.hermes/scripts/uai-short-monitor.py`、`~/.hermes/scripts/uai-short-monitor-state.py`
- Cron 任务：`uai-short-monitor-15m`（job_id：`947872a2c897`）
- `monitor` 使用 `uai-short-monitor-state.py`；状态输出必须不含当前时间、原始价格等每轮必变字段。
- agent 被唤醒后使用 detail 脚本重新读取一份新鲜快照，不能把 state 签名当作完整行情。

## 6. 验收与回滚

验收顺序：

1. `python3 scripts/hermes/uai-short-monitor.py --detail` 返回完整、带时间戳的报告。
2. `python3 scripts/hermes/uai-short-monitor-state.py` 返回稳定且可解释的状态签名。
3. 模拟数据错误/过期时输出 `DATA_ERROR` 和禁止交易措辞。
4. 复制脚本到 `~/.hermes/scripts/` 后再次实跑。
5. 创建 Cron 后先执行一次真实 run，核对输出目录、飞书投递和 `last_delivery_error=null`。（已验证：首轮输出 `2026-09-02_16-17-22.md`，任务状态 `ok`。）
6. 再检查任务列表，确认调度为 `*/15 * * * *`、投递目的为飞书、没有修改现有任务。
7. 审查加固后再次完成 14/14 测试、runtime 详细扫描和权限/副本核对；限流、坏K线、缺字段、未来/过期时间均有失败安全路径。

回滚：先暂停 `uai-short-monitor-15m`，必要时删除该任务；恢复脚本到部署前备份版本。现有 `radar-v2-hourly-review`、BTC 任务和生产 API 不得被修改。
